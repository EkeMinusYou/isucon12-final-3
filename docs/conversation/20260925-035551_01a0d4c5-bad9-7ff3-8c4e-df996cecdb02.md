## 1号機向け詳細設計

| 領域 | 設計 |
|---|---|
| 状態の所有 | 入口から認証・参照・更新までをユーザーID単位の一つの処理境界に入れる。同一ユーザーの操作は確定まで直列化する。 |
| 更新 | キャッシュ中の状態を直接変更せず、変更したフィールド・追加したID・確定済みの抽選結果を差分として組み立てる。MySQLへの確定後にだけキャッシュへ適用し、応答する。 |
| 永続化 | `user_state_events(user_id, seq, version, payload, digest)`を追加し、`(user_id, seq)`を主キーにする。差分を最大32件、最大1ms待ちで束ね、一つのトランザクションで挿入する。これらは開始値であり、効果はRUNで判定する。 |
| 復元 | 既存の`user_state_core`・`inventory`・`inbox`をスナップショットとして使う。キャッシュミス時はスナップショット以降のイベントを順に再生する。スナップショットのない初期ユーザーは公式初期データから読み込む。イベントが64件または64KiBに達したユーザーは、スナップショット更新と再生済みイベント削除を同一トランザクションで行う。 |
| メモリ | 状態とseedプレゼントのキャッシュを合計16MiB、セッション逆引きキャッシュを2MiBから始め、容量超過時は未使用エントリを退避する。最新RUNの1号機の空きメモリは最小約69MBであり、無制限の全件常駐は採らない。[同一RUN分析](/Users/mineo/worktrees/EkeMinusYou/isucon12-final-3/mon/docs/conversation/20260925-032234_01a0d4a7-3fc2-78d0-814c-d8333f7af810.md:477) |

**セッション。** 現行のログインは有効な旧セッションを範囲更新してから新規挿入します。[state_login.go](/Users/mineo/worktrees/EkeMinusYou/isucon12-final-3/mon/webapp/go/state_login.go:188) これを、ユーザーごとに現在の1件だけを持つ`user_session_current(user_id PRIMARY KEY, session_id UNIQUE, expired_at)`へ置き換えます。ログインの状態差分とセッション行を同じトランザクションで確定します。認証時はセッションIDから所有ユーザーを引き、所有者の状態ロック中に現行セッションとの一致と期限を再確認します。これにより旧セッションの即時失効、他人の有効セッションに対する403、無効・期限切れの401を維持します。逆引きキャッシュが外れた場合だけDBを読む設計です。

**プレゼント。** 初期プレゼントは既存の`user_presents`を読み取り専用の基データとし、ユーザーの初回プレゼント操作で取得・整列して容量制限付きキャッシュに載せます。受取済みseed IDと時刻、ガチャ・ログインで生成したプレゼントは状態イベントに記録します。一覧は整列済みのseedと動的プレゼントをマージし、`created_at DESC, id ASC`、ページ件数と`IsNext`を維持します。受取は要求IDを重複排除し、未受取の確認、アイテム付与、受取時刻を**一つの状態差分**として確定します。管理APIは受取済みを含む一覧を再構成します。[現行の一覧・受取仕様](/Users/mineo/worktrees/EkeMinusYou/isucon12-final-3/mon/webapp/go/state_present.go:21)

**正当性の境界。** イベントには残高などの確定値と発行済みIDを記録し、再生時に乱数やIDを再生成しません。ガチャ・カード強化ではワンタイムトークンの一度限りの消費を維持します。現行実装は有効トークンを消費した後に残高不足などで失敗してもトークンを戻さないため、その場合は消費だけを確定してからエラーを返します。[state_game.go](/Users/mineo/worktrees/EkeMinusYou/isucon12-final-3/mon/webapp/go/state_game.go:80) DB確定の成否が不明な場合は`(user_id, seq)`と`digest`で記録を照合し、二重適用を防ぎます。イベントの欠番・未知の版は黙って読み飛ばしません。
