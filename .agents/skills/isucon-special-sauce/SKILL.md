# ISUCON 秘伝のタレを現行設定へ適用

指定資料の設定を現行環境・公式仕様に合わせて実装し、正規deployする。これらは適用する設定候補として扱い、現在のRUNでスコア効果が見えていなくても導入する。ベンチはユーザーが実行する。

## 対象を選ぶ

- 指定があれば、`docs/special-sources/` 内のパス、ファイル名、カタログのリンク、一意な名称から対象を解決する。文書指定は文書全体、節・設定項目の指定はその範囲、複数指定は和集合だけを調べる。
- 指定がなければ `docs/special-sources/README.md` と実際のファイル一覧を照合し、ルート README 以外の全 Markdown 文書を調べる。カタログ未掲載の文書も含め、差分を報告する。
- 指定が曖昧または対象が存在しない場合は、対象を確認する。全件調査へ勝手に広げず、対象確定までは変更しない。

## 現行設定と照合して実装・deployする

指定資料を現行設定・コード・公式仕様と照合する。出典、現行値、採用する値、設定の生成元と反映先を確認し、未適用の項目を原則として導入する。RUNや計測結果はホストの容量と値の調整に使えるが、得点への寄与や現在の律速であることを適用条件にしない。

資料の数値は候補値なので、ホストのメモリー・接続数・ファイルディスクリプタ上限などに合わせて安全な値を選ぶ。公式要件と矛盾する、実効設定にならない、または現行資源では明らかに危険な項目だけ見送る。同じ効果が既に得られている項目は重複させず、未反映部分を適用する。見送った項目と値を変えた項目は理由を残す。

一体で反映すべき設定群はまとめて変更し、設定の生成元を編集する。生成物を直接編集せず、Taskfileと正規のdeploy経路を使う。deploy前に対象ホストとserviceへの影響を確認し、進行中RUNとdeploy/restartを重ねない。必要なローカル設定検査・buildを行い、deploy後は対象serviceと実効設定を確認する。

## 完了報告

指定対象／全件の別と調査文書、採用した差分、実装・deploy結果、出典リンク、見送った変更と理由を簡潔に報告する。ベンチを実行せず、計測で確認すべき効果を明記する。
